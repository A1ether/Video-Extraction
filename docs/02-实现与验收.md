**前端相关的工程发现**

| 现象 | 结论 / 修法 |
|---|---|
| 无头 Chrome `--dump-dom` 卡死 | SSE 长连接让页面永远处于加载中、虚拟时间不推进 → 增加正式的「实时推送」开关（设置项 + `?live=0`），关掉即轮询 |
| 所有封面都 400「拒绝访问内网地址」 | 本机 FlClash **TUN fake-ip** 把外部域名解析成 `198.18.x.x`，被 SSRF 守卫误判 → 不再按私有网段一刀切（真正的防线是 CDN 域名白名单），并补了 fake-ip 的回归测试 |
| `history.json` 不存在时 `UnboundLocalError` | `_persist()` 里 `rows` 未初始化（被前面的重构误删），任务一结束就抛 → 补初始化 + 用例 |
| **`vx serve` 把用户送到"要求登录 Claude"的别人家页面** | 默认端口用了 8000，而本机常驻的 `claude-science` 守护进程正好占着 8000/8001；更糟的是代码**先 `webbrowser.open()` 再启动 uvicorn**，绑定失败后用户面对的是别人的 UI → ① 默认端口改 8787；② 端口被占时自动让位并打印占用者（`lsof` 识别）；③ 浏览器只在"服务真的 started 且 `/health` 探活确认是本程序"之后才打开；④ 绑定失败（uvicorn `sys.exit(1)`）时自动换端口重试，最多 5 次 |
| 端口预检用 `SO_REUSEADDR` 导致漏判 | 实测：别的进程绑在 `0.0.0.0` 时，带 `SO_REUSEADDR` 探测 `127.0.0.1` 会返回"可用"（`bind` 成功），随后真正启动才撞车 → 预检去掉 `SO_REUSEADDR`（宁可严格），并加回归用例 |

## 3. 未验收部分（诚实清单）

| 项 | 状态 | 原因 / 下一步 |
|---|---|---|
| 小红书**视频**笔记正例 | ⚠️ 未线上验证 | 本机拿到的唯一带 `xsec_token` 的公开链接已失效（实测 302 → `/404`，我们的实现正确报 `NO_MEDIA`）。视频分支由按真实字段结构构造的 fixture 覆盖。**需要一条你手机 App 里复制的分享文本才能验收** —— 贴一条即可。 |
| 抖音正例 | ⚠️ 未验证 | 需要 cookie。跑 `vx get "<抖音分享文本>" --cookies-from-browser chrome` 即可验证（会读你本机 Chrome 的 cookie，不写、不打印）。 |
| 视频号 | ❌ 本期不做 | 无网页播放地址，需 MITM 证书 + 系统代理，且与常驻 TUN 代理冲突 → 规划为 P2 独立本地服务。 |
| 快手「作品不可见」那条 | ⚠️ 未用浏览器复核 | 可能是作品已删除；错误归类为 `NO_MEDIA` 是正确的（非解析失败）。 |

## 4. 开发期发现并修掉的真实缺陷

| 缺陷 | 症状 | 修法 |
|---|---|---|
| `PLATFORM_HOSTS["tiktok"] = ("tiktok.com")` 少逗号 | 不是元组 → 变成逐字符匹配，TikTok 链接永远识别不出平台 | 补逗号，并用参数化测试锁住 |
| `_CTRL` 只过滤 C0 控制字符 | 小红书 SSR JSON 里出现 U+0083（C1）时会 `json.JSONDecodeError` | 过滤范围扩到 C1 + BOM |
| 微博选流依赖返回顺序 | "best" 会选到标清（playback_list 顺序 ≠ 清晰度顺序） | 引入显式 `Stream.rank`，由各 provider 计算，下载器只认 rank |
| 快手走桌面 apollo state | 平台改版后必然 `NO_MEDIA` | 改走移动页 `INIT_STATE`（并保留桌面兜底分支） |
| 注册表自动发现取错包 | `from . import __name__` 拿到字符串 → provider 列表为空 | 改为 `importlib.import_module(".providers", __package__)` |
