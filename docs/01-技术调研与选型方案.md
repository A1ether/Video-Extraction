## 0. 结论摘要（先看这段）

| 决策项 | 结论 |

## 3. 技术选型

### 3.1 语言与运行时

**Python 3.12 + uv**。理由按权重排序：

1. **引擎复用是硬约束**：yt-dlp 是 Python，库内嵌可拿结构化 `dict` 和 `progress_hooks`；换 Go/TS 就只能 subprocess + 解析 stdout，而官方 README 明确 stdout 格式不可依赖。
2. **AI 辅助编程密度**：本任务全是"抓页面 → 解析 JSON → 拼签名 → 下载合并"，Python 的训练语料与生态（httpx/lxml/pydantic/curl_cffi）最厚。
3. **脚手架轻**：`uv init` + 单个 `pyproject.toml`，不引入 monorepo（对比 mediago 的 Go+Electron+TS 三语言工作区）。
4. 反面考量：Go 的 res-downloader 胜在单二进制分发，但我们本期不做 GUI，分发改 `uv tool install` 即可。

### 3.2 依赖（版本已在 Python 3.12 下真实解析通过）

| 用途 | 包 | 解析版本 | 许可证 |
|---|---|---|---|
| 引擎 | `yt-dlp` | 2026.10.21 | Unlicense |
| Web 框架 | `fastapi` / `uvicorn[standard]` | 0.162.0 / 0.54.0 | MIT / BSD |
| CLI | `typer` | 0.27.3 | MIT |
| 数据模型 | `pydantic` / `pydantic-settings` | 2.14.1 / 2.16.1 | MIT |
| HTTP | `httpx` | 0.28.1 | BSD |
| 终端输出 | `rich` | 15.0.0 | MIT |
| HTML 解析 | `lxml`（或标准库 `html.parser`） | — | BSD |
| 测试 | `pytest` / `respx` | — | MIT |
| 静态检查 | `ruff` | — | MIT |

**系统外部依赖：ffmpeg 9.0.2（已装）**。DASH 平台（B站/YouTube）音视频分离，不合并会得到"静音视频"，启动时必须探测并**硬失败**。

**不引入**：`curl_cffi`（TLS 指纹）本期不做——B站/微博/快手/小红书都不需要；Playwright 不做——只在小红书需要登录态时才用，走可选 sidecar。

### 3.3 为什么这个栈"利好 vibe coding"

| 约束 | 落地手段 |
|---|---|
| 脚手架简洁 | 单 `pyproject.toml` + `src/` 布局，`uv run vx ...` 一条命令起 |
| 错误提示明确 | 单一错误基类带 `code` + `hint` + `platform`；CLI 渲染 hint，HTTP 返回 code；每个 code 对应"用户下一步该做什么" |
| 便于 AI 迭代 | 一个平台一个文件、两方法 Protocol、注册表按顺序匹配——新增平台=新增一个文件，无需改路由 |
| 改完即可验 | `pytest` 全程离线（fixture 驱动），单测不碰网络；另有一组 `-m live` 真机测试 |
| 结构可推断 | 分层固定 `urls → registry → provider → models → download`，AI 不用猜文件放哪 |

### 4.2 快手解析路线的实测修正（开发期新增证据）

调研阶段（子代理报告）记录的是「桌面页 `__APOLLO_STATE__` → `VisionVideoDetailPhoto`」路线，
开发期实测推翻了这个结论，三条路线逐条验证如下：

| 路线 | 实测结果 |
|---|---|
| 桌面 `www.kuaishou.com/short-video/<id>` 的 `__APOLLO_STATE__` | ❌ 200 且 76KB，但 `VisionVideoDetailPhoto` 出现 **0** 次；`__typename` 只有 `VisionTab/Banner/VisionConfigResult/SubTab` → **只剩 UI 配置** |
| 桌面 GraphQL `POST /graphql`（带首页下发的 `did` cookie） | ❌ 返回 `result:400002` + `captcha.zt.kuaishou.com` 验证码 URL → 无浏览器不可行 |
| **移动页 `m.gifshow.com/fw/photo/<id>` 的 `window.INIT_STATE`** | ✅ 命中：顶层键做了 -1 凯撒位移（值为明文），`photo/simple/info` 节点内含 caption / duration / userName / `mainMvUrls` / `manifest.adaptationSet[].representation[]` |

实测样本：4 个来自公开代码的真实作品 ID，**3 个成功**（720p avc+hevc 双码流 + origin 兜底，
下载产物 ffprobe 为 `h264 720x1280 + aac`，时长与解析出的 9250ms 一致），第 4 个返回
「作品可能已删除/仅粉丝可见」——错误归类正确，未误报为解析失败。

### 4.3 抖音：cookie 是 "第一道闸"，不是全部（2026-10-25 实测）

用户用 Cookie-Editor 导出了 70 条登录态 cookie（含 `UIFID`/`sessionid`/`ttwid`/`s_v_web_id`）。
全部导入 L1 文件后逐条实测，结论是：**cookie 有效但远不充分**。

| 请求 | 结果 |
|---|---|
| `yt-dlp -J`（带 70 条 cookie） | ❌ 仍报 `Fresh cookies (not necessarily logged in) are needed` |
| `GET /aweme/v1/web/aweme/detail/?aweme_id=<id>`（带全部 cookie，PC UA / 移动 UA / 暖手首页后） | ❌ 403 `Blocked by ArgusSecurityPlugin Uifid Not Found` |
| 同上 + `uifid=<cookie 里的 UIFID>` 查询参数 | ❌ 403 `... Signature Not Found` ← **闸门推进了一步**，说明 uifid 是 Argus 要的第一项 |
| 同上 + 把 uifid 放请求头 | ❌ 同样是 `Signature Not Found` |
| 对比：第三方解析接口（本地零 cookie） | ✅ `code:0 解析成功`，返回 540p mp4 直链（HTTP 206 / `video/mp4` 实测可下） |

也就是说 Argus 需要**两件**东西：① `uifid` 以查询参数回传；② `a_bogus` 加签。
yt-dlp 的 `DouyinIE` 两件都不做（源码注释就是 `TODO: Run verification challenge code`），
所以"再导一次 cookie"永远不会成功 —— 这不是配置问题，是引擎不实现签名。

**因此抖音的三条现实路线**（未决，留给下一阶段）：

| 路线 | 代价 | 备注 |
|---|---|---|
| 转发第三方解析接口 | 低（一个 HTTP 调用）；依赖别人、有速率与隐私代价 | 本机已实测可用（见上表末行） |
| 本地复现签名 + 自研 provider | 中高：要跟签名改版 | **← 已采用，见 §4.4** |
| 维持现状（抖音报明确错误，其它平台可用） | 零 | 已放弃：能做到就别留着 |

### 4.4 抖音自研落地：Argus 要的不是 a_bogus（2026-10-25 定案）

§4.3 里把"缺 a_bogus"当成了结论，**这一步判断错了**。逐项拆开验证后真相是：
Argus 校验的是另一个更短、更简单的签名。

**拆解过程**（每步都只改一个变量）：

| 请求 | 结果 | 读出的结论 |
|---|---|---|
| 全 cookie + 无任何签名参数 | 403 `Uifid Not Found` | 第一道闸是 uifid |
| + `uifid` 查询参数 | 403 `Signature Not Found` | 第一道过了，露出第二道 |
| 用 dtk 的纯 Python `a_bogus` 补 `a_bogus` 参数 | **仍 403 `Signature Not Found`** | a_bogus 不是这一道要的东西 |
| 换成 dtk 的 `x-secsdk-web-signature`（md5）| **200，取到完整 aweme_detail** | ✅ 真正的闸门是它 |
| 有签名、**故意不带 `a_bogus`/`msToken`/`verifyFp`** | **200，照样完整** | 这几个参数在该接口上**非必需** |

**签名算法**（无 nonce、无状态、纯函数，50 行可写完）：

```
query = "&".join(f"{quote(k)}={quote(v)}")   # 覆盖所有业务参数 + uifid + timestamp，顺序敏感
sig   = md5(f"{uifid}_{timestamp}_{SALT}_{query}").hexdigest()   # 32 位 hex
SALT  = "A96D855A08C0A9707F8BEF0D9A527E4E"   # douyin_web 的 project-id=34 常量
```

**正确性证据（不是"能跑通就算对"）**：平台只抽样校验，200 可能只是运气。所以用抖音自己的
浏览器发出的请求当 oracle：

```
从无头 Chrome 的 performance entries 取抖音自己构建的 URL
→ 剥掉 x-secsdk-web-signature 本身，其余参数按原顺序重拼
→ md5(uifid_ts_SALT_query)
→ 与浏览器给出的 32 位签名逐字节比对：**match: true**（两组样本，38 参数与 7 参数各一）
```

**身份三件套的可得性**（逐项实测，决定要不要用户 cookie）：

| 组件 | 能否本地生成 | 证据 |
|---|---|---|
| `ttwid` | ✅ 能 | `POST ttwid.bytedance.com/ttwid/union/register/` 免费下发游客 ttwid（127 字符），缓存 3 天 |
| `x-secsdk-web-signature` | ✅ 能 | 上面的纯函数；已与浏览器输出对齐 |
| `UIFID` | ❌ 不能 | 首页/详情/分享页/hot list/comment list 逐个试：**没有一个 Set-Cookie 下 uifid**。随机值 → 403 `Validate Error` |
| `a_bogus` / `msToken` / `verifyFp` | 不需要 | 去掉照样 200 |

**其他实测细节**：`Referer` 必需（缺了返回 200 + **0 字节**，极易被误判成"作品不存在"）；
直链裸请求 403、带 Referer 200；下载产物 `h264 1080x1920 + aac`，19.733s，6.0 MB，无抖音水印。

**为什么最后是自己写 50 行、而不是 vendor dtk 的实现**：dtk 那两个文件是 Apache-2.0，可以直接
依赖，但只为了一个 md5 就背上它的传输层/配置层不划算。算法本身（salt 常量 + md5 拼串）无法被
版权保护，这里按"读实现、自己写、用平台真实输出做对拍"处理 —— 与 §5.1 对 GPL 条文的要求一致，
并且对拍证据比任何自述都硬。

## 6. 架构设计

### 6.1 分层

```
share text/URL
   │
   ├─ urls.py        分享文本 → 规范化 URL（含短链 302 展开）
   │
   ├─ registry.py    按顺序询问 provider：matches()?
   │
   ├─ providers/     每个平台一个文件：matches() + resolve() → MediaInfo
   │    ├─ bilibili.py   自研 WBI + playurl（DASH）
   │    ├─ weibo.py      游客墙 + statuses/show（单 mp4）
   │    ├─ kuaishou.py   __APOLLO_STATE__
   │    ├─ xhs.py        __INITIAL_STATE__
   │    ├─ douyin.py     yt-dlp + cookie 阶梯
   │    └─ ytdlp_generic.py  YouTube/TikTok/其余 1700+ 站点
   │
   ├─ models.py      MediaInfo / Stream（统一中间表示）
   │
   ├─ download.py    选流 → 下载 → ffmpeg -c copy 合并 → 命名落盘
   │
   ├─ cli.py         typer：info / get / platforms / doctor
   └─ api/           FastAPI：/extract /download /platforms /health
```

### 6.2 统一中间表示

```python
class Stream(BaseModel):
    url: str
    quality: str          # "1080p" / "720p" / "audio-192k"
    ext: str = "mp4"
    codec: str | None
    audio_only: bool = False
    bitrate: int | None
    filesize: int | None  # 直链不带长度时为 None

class MediaInfo(BaseModel):
    platform: str
    media_id: str
    source_url: str
    title: str
    author: str | None
    cover_url: str | None
    duration: float | None
    stats: dict[str, int] = {}      # view/like/comment
    streams: list[Stream]
    needs_merge: bool = False       # True → 必须 ffmpeg
    extra: dict = {}                # 弹幕/字幕/合集等平台私有字段
```

### 6.3 cookie 阶梯（抖音/高清 B站）

严格按"一级一报错"，**绝不静默重试**：

| 级 | 动作 | 失败时 |
|---|---|---|
| L0 | 无 cookie 直连 | 抛 `AUTH_REQUIRED`，hint 指明 L1 |
| L1 | 读 `~/.config/vextract/cookies/{platform}.txt`（Netscape 格式） | 抛 `AUTH_REQUIRED`，hint 给导出命令 |
| L2 | `--cookies-from-browser <name>` 导入 | 抛 `AUTH_REQUIRED`，hint 给手动导出步骤 |

### 6.4 错误码

| code | 含义 | hint 指向 |
|---|---|---|
| `UNSUPPORTED_URL` | 没有 provider 认领 | 列出支持的平台 |
| `URL_NOT_FOUND` | 分享文本里没找到链接 | 让用户贴完整分享文本 |
| `AUTH_REQUIRED` | 需 cookie/登录 | 给具体导出命令 |
| `RATE_LIMITED` | 403/429/风控 | 建议换 IP、降频 |
| `UPSTREAM_CHANGED` | 页面结构变了（解析出 None） | 报 issue 并附 `--debug` 输出 |
| `NO_MEDIA` | 该条是图文/无视频 | 说明原因 |
| `DEPENDENCY_MISSING` | ffmpeg 缺失 | 安装命令 |
| `DOWNLOAD_FAILED` | 落盘/合并失败 | 附路径与 stderr 尾部 |

## 10. 决策记录（ADR）

- **ADR-001 引擎不 fork yt-dlp。** 理由：fork 要长期 rebase，而 B站/YouTube 修复频率极高（近 90 天 79 次提交）；库内嵌 + 自研 provider 能让上游修复自动继承。
- **ADR-002 快手/小红书自研，不做通用"网页嗅探器"。** 理由：通用嗅探（mediago 路线）需要 GUI 或扩展，与"贴链接出文件"的服务模型冲突；两个平台都有稳定的 SSR 内嵌 JSON。
- **ADR-003 抖音不做 a_bogus 自研。** 理由：Apache-2.0 实现是 JS（要引 Node 运行时），纯 Python 实现多无许可证；且即使签名通过仍受 uifid 身份风控。先交付 cookie 阶梯，把工程量留给 P1。
- **ADR-004 错误码优先于异常文本。** 理由：便于 AI 迭代时定位"这一层该改哪里"，也便于 HTTP 客户端做重试策略。
