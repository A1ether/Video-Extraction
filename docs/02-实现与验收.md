### 2.4 抖音：从"cookie 不够"到自研打通（2026-10-25 追加实测）

第一步：用 Cookie-Editor 导出的 70 条登录 cookie 落成 L1 文件，**没能解锁**抖音：

```
$ uv run vx cookies import <导出文件> --platform douyin
✔ 已写入 ~/.config/vextract/cookies/douyin.txt (70 条 cookie，权限 600)
$ uv run vx info "https://www.douyin.com/video/6961737553342991651"
ERROR: [Douyin] …: Fresh cookies (not necessarily logged in) are needed
403  Blocked by ArgusSecurityPlugin Uifid Not Found          ← 直接打接口
+ uifid 查询参数 → 403  ... Signature Not Found              ← 闸门前进了
```

第二步：按"一步只改一个变量"继续拆，发现**真正要的不是 a_bogus**（详见 docs/01 §4.4）：

```
补 a_bogus（dtk 纯 Python 实现）      → 仍 403 Signature Not Found
换成 x-secsdk-web-signature（md5）     → 200 ✅ 完整 aweme_detail
有签名、故意删掉 a_bogus/msToken/fp   → 200 ✅ 照样完整
```

第三步：用抖音自己的浏览器请求当 oracle，核对签名实现（不是"能跑就算对"）：

```
抖音浏览器发出的 URL → 剥掉签名参数本身，其余按原顺序重拼
→ md5(uifid_ts_SALT_query) 与浏览器给出的 32 位签名比对
→ 两组样本（38 参数 / 7 参数）全部 match: true
```

**前端相关的工程发现**

| 现象 | 结论 / 修法 |
|---|---|
| 无头 Chrome `--dump-dom` 卡死 | SSE 长连接让页面永远处于加载中、虚拟时间不推进 → 增加正式的「实时推送」开关（设置项 + `?live=0`），关掉即轮询 |
| 所有封面都 400「拒绝访问内网地址」 | 本机 FlClash **TUN fake-ip** 把外部域名解析成 `198.18.x.x`，被 SSRF 守卫误判 → 不再按私有网段一刀切（真正的防线是 CDN 域名白名单），并补了 fake-ip 的回归测试 |
| `history.json` 不存在时 `UnboundLocalError` | `_persist()` 里 `rows` 未初始化（被前面的重构误删），任务一结束就抛 → 补初始化 + 用例 |
| **`vx serve` 把用户送到"要求登录 Claude"的别人家页面** | 默认端口用了 8000，而本机常驻的 `claude-science` 守护进程正好占着 8000/8001；更糟的是代码**先 `webbrowser.open()` 再启动 uvicorn**，绑定失败后用户面对的是别人的 UI → ① 默认端口改 8787；② 端口被占时自动让位并打印占用者（`lsof` 识别）；③ 浏览器只在"服务真的 started 且 `/health` 探活确认是本程序"之后才打开；④ 绑定失败（uvicorn `sys.exit(1)`）时自动换端口重试，最多 5 次 |
| 端口预检用 `SO_REUSEADDR` 导致漏判 | 实测：别的进程绑在 `0.0.0.0` 时，带 `SO_REUSEADDR` 探测 `127.0.0.1` 会返回"可用"（`bind` 成功），随后真正启动才撞车 → 预检去掉 `SO_REUSEADDR`（宁可严格），并加回归用例 |

## 4. 开发期发现并修掉的真实缺陷

| 缺陷 | 症状 | 修法 |
|---|---|---|
| `PLATFORM_HOSTS["tiktok"] = ("tiktok.com")` 少逗号 | 不是元组 → 变成逐字符匹配，TikTok 链接永远识别不出平台 | 补逗号，并用参数化测试锁住 |
| `_CTRL` 只过滤 C0 控制字符 | 小红书 SSR JSON 里出现 U+0083（C1）时会 `json.JSONDecodeError` | 过滤范围扩到 C1 + BOM |
| 微博选流依赖返回顺序 | "best" 会选到标清（playback_list 顺序 ≠ 清晰度顺序） | 引入显式 `Stream.rank`，由各 provider 计算，下载器只认 rank |
| 快手走桌面 apollo state | 平台改版后必然 `NO_MEDIA` | 改走移动页 `INIT_STATE`（并保留桌面兜底分支） |
| 注册表自动发现取错包 | `from . import __name__` 拿到字符串 → provider 列表为空 | 改为 `importlib.import_module(".providers", __package__)` |
| **yt-dlp 会改写用户的 cookie 文件** | 把 `douyin.txt` 交给 yt-dlp 跑一次，退出时它的 cookie jar 会 `save()` 回原路：实测 **70 条被削成 66 条**（`sdk_source_info`/`bit_env`/`gulu_source_res`/`passport_auth_mix_state` 消失），文件头还被换成 yt-dlp 的注释。用户会以为"导入成功了"，其实 cookie 被引擎悄悄吃掉一部分 | engine 层改为**影子副本**：复制到临时 0600 文件再交给 yt-dlp，`finally` 里删除；原文件一个字节都不动。补回归测试：跑前跑后 `shasum` 必须一致 |
| Cookie-Editor 导出的空 name 占位行 | 71 条里有 1 条 `"name": ""` 的站点标记，写进 Netscape 会多出一行垃圾 | 导入时丢弃并说明原因（"Cookie-Editor 的站点占位行"） |

## 5. 下一步（P1 建议）

1. 小红书视频笔记正例：需要一条你手机 App 里复制的、带 `xsec_token` 的分享文本。

4. 每日探测任务：跑 `pytest -m live`，把失败按平台记成可观测指标（这是本项目最大的风险面）。

   而不是等用户发现下载失败。

## 6. 抖音这一轮踩过的坑（写给后来者）

| 坑 | 表现 | 真相 |
|---|---|---|
| 以为"必须补 a_bogus" | 补了 dtk 的纯 Python a_bogus 仍 403 | 该接口的闸门是 32 位 md5（`x-secsdk-web-signature`），a_bogus 根本不是必需项 |
| 以为"cookie 越多越稳" | 70 条登录 cookie 照样 403 | 只有 `UIFID` + `ttwid` 两项参与，其余 cookie 与成败无关 |
| 以为 200 就代表成功 | 200 但 body **0 字节** | 这是 `Referer` 被剥掉的症状，误判成"作品不存在"会白查半天 |
| 以为"随机造个 uifid 就行" | 403 `Validate Error` | UIFID 必须是服务端登记过的值，随机构造过不了 |
| 签名"能跑通"就当对 | 平台只抽样校验，可能只是运气 | 必须拿平台自己的浏览器输出做逐字节对拍（本仓库做法见 docs/01 §4.4） |
| 竖屏分辨率按 height 标档 | 1080x1920 被标成 1920p | 档位看 `gear_name`（`normal_1080_0`），或按短边算 |
| 以为 cookie 文件"只读" | 交给 yt-dlp 跑一次，70 条变 66 条（文件头换成 yt-dlp 的注释） | yt-dlp 退出时会 `save()` cookie jar 回原路径 —— engine 必须给影子副本，不能直接给用户文件 |
