# 03 · 拓展能力：仅音频 / 图集 / 本地转录（v0.3）

v0.2 只做"无水印视频"。这一轮把同一个分享链接能拿到的**另外三种产物**做成了正式功能：
**仅音频**（可选转码 + 标签）、**图集**（图文作品）、**本地转录**（音频 → 文字稿）。

口径不变：**不采信上游 README 的自述，只认本机实测**。本文每条"支持/不支持"都带实测数字，
探针脚本可复现：`uv run python scripts/probe_extras.py`，真机用例：`uv run pytest -m live`。

| B站弹幕 | 匿名 `x/v1/dm/list.so?oid=<cid>` → **deflate** XML，三条样本 862 / 16 / 1200 条（`zlib.decompressobj(-zlib.MAX_WBITS)`） | ⏳ 未做（保持 P2；见 docs/01 的 P2 清单） |

### 为什么"字幕"这条线最终落在本地转录

国内平台的 CC 字幕是**登录态产物**（上表两条 ❌）。与其做一个"匿名必空"的字幕功能，
不如让音频走本地 ASR：与平台改版无关、离线可用，产出的 `.srt` 还能反过来内嵌回视频。

### VAD 对照：同两条音频，两个后端（实测）

| 音频 | mlx_whisper + small | faster_whisper + small（`vad_filter=True`） |
|---|---|---|
| TTS 合成中文（有人声，14s） | 正确（1 段，重复度 0.000） | 正确，3.3s（1 段，重复度 0.000） |
| TTS 合成中文 8 句（有人声，65s） | 正确（8 段，重复度 **0.007**，未误判） | 正确（7 段，重复度 **0.007**，未误判） |
| 微博 53s（狗视频，基本没人声） | 编出 8 次「最后一切都出现了」，**且没被闸门拦下**（重复度 0.36 < 0.4） | **空结果 → `TRANSCRIBE_FAILED: 转录结果为空`** |
| B站分P 564s（日文游戏剧情，**有人声**） | 塌成「我看你不太好」×N → 被判重拦下 | 50 段 / 366 字真实台词（Wisthet Wanderland… 鏡よ鏡…） |

结论：① 判重闸门只挡得住"极端循环"，挡不住"轻度编造"（微博那条 0.36 就漏了）——所以 faster-whisper 的
VAD 是更前面的那道闸；② mlx 在长音频上会塌，**同一个文件换 faster-whisper 就能拿到真实台词**，
所以 `--asr-backend` 不是装饰品；③ 两段长语音（65s/564s）重复度都在 0.01 以下，闸门不误伤正常内容。

**CLI 端到端（2026-10-25，`?p=3` 分P · 6:48 · 12.0MB 音频 · faster_whisper·small · av 18.1.0）**：
`端到端.m4a` 12.0MB + `端到端.md` 2.2K，正文是真实剧情台词（中日混排，与剧情对得上）。
同时确认三件事一次跑通：`--asr-backend` 在 CLI→download→asr→落盘的真实链路上生效、
进度文案显示的是 `faster_whisper·small` 而不是自动挑的后端、`?p=3` 选到的就是 6:48 那一分P。

> **已知残留**：即使换了 VAD 后端，6:48 这条的尾部仍有局部重复（`那套套套套…` 连续若干字），
> 整体重复度低所以闸门不报。判重是**整段**指标，只能拦"整段塌陷"，拦不住"局部退化"——
> 需要逐段（per-segment）判重才治得好，留作后续。

### 字幕：从"不要承诺"到"能下"的关键一步

登录态能拿到字幕，但**自研 provider 读不到"从浏览器读取 cookie"这个设置**——那个设置原先只传给 yt-dlp，
而 B站/抖音/小红书走的是 `http.client()` 这个 httpx 工厂。于是"登录后才有的东西"对只用浏览器登录的用户不可达。
现在 `http.browser_cookies()` 会在没有 L1 cookie 文件时，按平台域名从浏览器**只读**取一份（不写、不落盘、不打印），
`cookies_from_browser` 设置对所有 provider 生效。

> 注意：字幕轨语言码是平台自定的（`zh-CN` / `ai-zh` / `ase`=美国手语…），`--subs auto` 的偏好顺序是
> 人工简体 > 人工通用 > AI 中文 > 繁体 > 英文；指定不存在的语言会报错并列出全部可选轨。

### 抖音图文踩到的两个坑（都会让产物"看着对、其实错"）

1. **图文作品也带 `video.play_addr`**：那是自动合成的幻灯片（`duration=0`、`bit_rate` 为空），
   但 `_streams()` 照样把它当成一路"视频流" → 图集被默认模式下成 **0.7MB 的 mp4**，
   而不是 6 张原图（`vx info` 还显示"1 streams · 视频作品"）。现在有图就丢掉视频流。
2. **两套图片地址**：`url_list`（`tplv-dy-aweme-images`，无水印）与 `download_url_list`
   （`tplv-dy-water-v2`，**带水印**）。取错就把水印图发给用户，而"无水印"正是这个项目的卖点。
   另外同批同时给 webp/jpeg，默认挑 jpeg（不是所有看图/剪辑工具都吃 webp）。

> 顺带修了个我自己引入的回归：改图片格式优先级时把 `_first_url` 的参数名从 `node` 改成 `block`，
> 函数体还在用 `node` → 抖音每条 resolve 都会 NameError。**封面路径此前没有任何用例覆盖**，
> 所以立刻补了一条 `test_cover_url_is_parsed_from_cover_block`。

### 逐段判重的阈值取舍（为什么是"3 次 + 12 字"）

- 只判整段时，6:48 那条真实剧情的局部循环（重复度远低于 0.4）会漏掉；
- 逐段用"同一 2~8 字片段连续 ≥3 次"能抓住 `你不太好你不太好你不太好` 与 `套套套套…`；
- 但 `哈哈哈哈哈哈哈哈`（8 字笑声）不该被标 → 加"整段 ≥12 字"门槛；
- 代价：`對對對對對對對對` 这种强调式重复也会被标，所以文案只写"疑似"，不下结论，并提示回原声核对。

### 一处自相矛盾（写 hint 时暴露）

重复幻觉的 hint 里写着「改用 faster-whisper 后端（自带 VAD）」，但 `--asr-backend` **当时根本不存在**——
CLI/HTTP/设置页都没有选后端的入口，照着提示做只会撞墙。已补上 `--asr-backend`（连同
`asr_backend` 配置项、`TaskRequest.asr_backend`、设置页下拉、`/doctor` 的 `choices`），
并加了用例钉住"hint 点名的后端必须是 CLI 真的收的值"。

> 教训：写"你下一步该做什么"的提示时，要顺手确认那个动作真的存在；本项目所有错误都带 hint，
> 这个坑每个 hint 都可能踩。

### 顺手修掉的缺陷（本轮实测暴露）

0. **B站多分P 合集：界面报总时长、产物只给第 1 分P**（v0.2 起）。实测 `BV1JE411N7UD` 是 21 个分P、
   总时长 7330s，但 `view.duration` 是**合集总时长**而 `data["cid"]` 只是第 1 分P（564s）——
   于是 `vx info` 显示 122:10，下回来的音频只有 9:24（我先怀疑是下载截断，`ffprobe` 对过才确认是选集问题）。
   现在按链接里的 `?p=N` 选集、`duration` 用**该分P**的时长，并在提示里写明"共 21 个分P（总时长
   2:02:10），本次只处理第 1 分P（开头 · 9:24）"；`p` 超范围会回退并在提示里说明。
1. **`av` 版本把 faster-whisper 整个搞挂**：`faster-whisper 1.2.1` 声明 `av>=11`，但内部调用
   `av.open(..., metadata_errors="ignore")`，而 **av 19.0 起不再接受这个关键字**——实跑直接
   `TypeError: open() got an unexpected keyword argument 'metadata_errors'`（实测 av 19.0.2 崩、18.1.0 正常）。
   依赖里钉 `av>=11,<19`，错误层也加了针对性翻译（见到该 TypeError 就直接告诉你装 `av<19`）。


1. **`Content-Type` 恒为 `application/octet-stream`**：`api/app.py` 的 `_media_type` 写成
   `PurePosixPath(path.suffix.lower()).suffix`（把 ".jpg" 当路径再取一次后缀 → 永远空串）。
   连带影响视频内嵌播放、图片预览。现改为直接查表；实测 `/tasks/{id}/artifact?index=0`
   的返回头从 `application/octet-stream` 变成 `image/jpeg`，`01.jpg` 确实是 6385×3592 的 JPEG。
2. **同名重下会把 media_id 写两遍**：冲突时拼的是 `stem_{media_id}`，而自动 stem 本身已以
   `_<media_id>` 结尾 → 实测目录名 `…_5357907014320571_5357907014320571`。
   现统一改成加序号（`…_2` / `…_3`），并加了"连续下三次"的回归用例。
3. **（测量口径，非代码问题）** 第一次统计模型体积时 `du -sh` 报 **20K**，那是错的：
   HuggingFace 缓存是 `snapshots/` 里放指向 `blobs/` 的**符号链接**，`du` 默认不跟随。
   加 `-L` 后实测：`whisper-tiny-mlx` **163MB**、`whisper-small-mlx` **918MB**
   （权重文件 `weights.npz` 71MB / 459MB）。要报体积就用 `du -shL`。

### 行为变更（可能让老脚本意外，故单列）

1. **图文作品不再是错误**：抖音/小红书/微博的图文以前抛 `NO_MEDIA`，现在返回 `MediaInfo.assets`
   （`is_image_post=True`）。视频模式对它下载会给出明确 hint（改用图集模式）。
2. **`-q audio` / `quality=audio` 不再是"静默回退到最佳视频"**：`Quality` 里那个 `audio` 档从
   v0.2 起就在，但 `pick_streams` 一直把它当普通清晰度过滤（匹配不到 → 回退最佳视频）。
   现在它等同 `--mode audio`。
3. 图集任务的 `task.path` 是**目录**，`/tasks/{id}/file` 对它返回 409；
   用 `/tasks/{id}/artifact?index=N` 取单张或「在访达中显示」。
